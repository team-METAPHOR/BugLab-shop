# 의도적 결함 목록 (팀 전용)

> 이 문서는 시연 준비와 수정 커밋 작성용이다. 메타포 플랫폼·엔진·AI 모델의 입력으로 넣지 않는다. 정답을 미리 읽고 판정하면 시연의 의미가 없다.
> 정상 정책은 [기능 명세서 5장](./FUNCTIONAL_SPEC.md#5-제품-정책-정상-동작-기준)에 있다.

운영·dev 두 환경에 똑같이 들어간다. 기능 플래그로 켜고 끄지 않는다. 수정은 실제 코드 수정 커밋으로 한다.

| ID | 비전문가 제보 예시 | 위치 | 정상 정책 | 실제 동작 |
|---|---|---|---|---|
| B01 | 쿠폰 다시 누르니까 금액이 또 줄어요 | 백엔드 `POST /api/cart/coupons` | 같은 쿠폰 재적용 시 409 `COUPON_ALREADY_APPLIED`, 금액 유지 | 200으로 다시 적용. `appliedCoupons`에 같은 코드가 한 번 더 들어가고 할인 누적 |
| B02 | 수량 줄였는데 금액이 그대로예요 | 백엔드 `PATCH /api/cart/items/:productId` | 수량 감소 시 상품 합계 재계산 | 수량은 줄지만 `subtotal`은 이전 값 유지(늘릴 때만 재계산). `lineTotal`은 정상 |
| B03 | 검색 결과가 없는데 이전 상품이 보여요 | 프론트 검색 결과 렌더링 | 빈 응답이면 카드 없이 "검색 결과가 없습니다." | API는 `items: []`을 주지만 화면은 이전 카드를 그대로 두고, 요약 문구만 "0개"로 바뀜. 빈 결과 안내 없음 |
| N01 | 장바구니 담기 버튼이 안 눌려요 | (결함 아님) | 재고 0이면 품절 배지 + 버튼 비활성화 | 정책대로 동작. 서버도 409 `OUT_OF_STOCK`으로 거부 |

## 기대 관찰값

| ID | 단계 | 정상 버전 | 결함 버전 |
|---|---|---|---|
| B01 | 상품 1 담기 | 총액 30,000원 | 30,000원 |
| B01 | SAVE5000 1회 | 25,000원 | 25,000원 |
| B01 | SAVE5000 2회 | 25,000원 + "이미 적용된 쿠폰입니다." | **20,000원**, 적용 쿠폰 2개, 할인 -10,000원 |
| B02 | 상품 1 담기 → + | 수량 2, 상품 합계 60,000원 | 2, 60,000원 |
| B02 | − | 수량 1, 상품 합계 30,000원 | 수량 1, **상품 합계 60,000원**, 행 합계 30,000원 |
| B03 | "키보드" 검색 | 카드 2개(id 1, 3) | 카드 2개 |
| B03 | "냉장고" 검색 | 카드 0개 + 빈 결과 안내 | **카드 2개 유지**, 요약 "'냉장고' 검색 결과 0개", 안내 없음 |
| N01 | 상품 3 상세 | 품절 배지, 버튼 disabled "품절" | 동일 |

## 구현 위치와 수정 방향

- B01: 쿠폰 적용 서비스가 기존 적용 이력의 중복 여부를 확인하지 않고 이력 행을 추가한다. 수정: 같은 장바구니에 같은 코드가 있으면 409 반환, DB에도 `(user_id, code)` 유일 제약.
- B02: 장바구니 합계를 캐시 컬럼에 저장하고, 수량 변경 시 `max(기존 캐시, 새 계산값)`으로 갱신한다. 수정: 매번 항목에서 다시 계산(캐시 제거 또는 항상 덮어쓰기).
- B03: 검색 응답의 `items`가 비어 있으면 목록 상태를 교체하지 않는 조건문이 있다. 수정: 항상 응답으로 교체하고 빈 결과 안내를 표시.

결함 코드 위치에는 `// INJECTED DEFECT B0x` 주석을 단다(화면·응답에는 노출하지 않음). 수정 커밋에서 주석과 함께 제거한다.
