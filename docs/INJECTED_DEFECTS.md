# 의도적 결함 목록 (팀 전용)

문서 버전: v2.0 (2026-11-05)

> 시연 준비·개발·수정 커밋 작성용 정답표다. 메타포 플랫폼·엔진·AI 모델의 입력으로 넣지 않는다.
> 정상 기대 동작은 [기능 명세서](./FUNCTIONAL_SPEC.md), 행동과 selector 계약은 [Playwright 실행 계약](./PLAYWRIGHT_CONTRACT.md)을 사용한다.

상품 6개에 대표 결함 1개씩을 배정했다. production·dev에 같은 코드로 존재하며 기능 플래그로 끄지 않는다.
로그인 자체는 정상이다. 이번 구현에는 정보 부족/인증 조건 부족 시연용 추가 결함을 넣지 않았다.

## 1. 현재 결함 6개

| ID | 상품 | 필요한 선행 조건·행동 | 눈에 보이는 실제 결과 | 정상 대조 |
|---|---|---|---|---|
| B01 | 1 무선 키보드 | 빈 장바구니에 1개 담기 → SAVE5000 적용 → **새로고침** → 같은 코드 재적용 | 최종 금액 **30,000 → 25,000 → 20,000원**, 쿠폰 이력 2개 | 같은 화면에서 바로 재적용하면 거부. 키보드 없는 장바구니는 새로고침 후에도 거부 |
| B02 | 2 저소음 마우스 | 1개 담기 → 장바구니 `+` → `−` | 수량 **1**, 행 금액 **18,000원**, 상품 합계 **36,000원** | 다른 재고 있는 상품의 수량 감소는 합계 재계산 |
| B03 | 3 기계식 키보드 한정판 | 재고 있는 상품 상세 → 하단 **함께 둘러볼 상품**에서 한정판 선택 | 품절 배지·재고 문구는 **품절**, 담기 버튼은 **활성화**. 클릭하면 서버가 품절 오류 반환 | `/products/3` 직접 진입·새로고침은 버튼 비활성화 |
| B04 | 4 USB 멀티 허브 | 로그인 → `허브` 검색 → 검색 결과 **빠른 담기 한 번** → 장바구니 | POST 2회, 수량 **2**, 합계 **84,000원** | 허브 상세의 담기는 1개. 다른 상품의 검색 빠른 담기도 1개 |
| B05 | 5 데스크 매트 XL | 로그인 → 상세에서 찜 → **새로고침** → 찜 해제 → **새로고침** | 해제 직후 하트·찜 개수는 사라지지만 다시 **찜 상태 복원**, 찜 목록에 남음 | 매트를 새로고침 없이 바로 해제하면 정상. 다른 상품은 새로고침 후 해제도 정상 |
| B06 | 6 원목 모니터 받침대 | 홈 상품 카드 → 받침대 상세 → **배송 안내** → 브라우저 **뒤로 가기** | URL은 홈인데 **받침대 배송 팝업이 계속 화면을 가림**, 배경 스크롤·조작 잠금도 유지 | 다른 상품은 페이지 이탈 시 자동 닫힘. 받침대도 X·확인·Escape·배경 클릭으로 닫기는 정상 |

금액은 해당 상품만 담고 별도 쿠폰을 적용하지 않은 기준이다(B01 제외).

## 2. 재현 시 주의

- B01/B02/B04/B05는 정상 로그인이 필요하다. B03의 버튼 상태 관찰과 B06은 로그인 없이도 가능하다. B03의 서버 품절 오류까지 확인하려면 로그인한다.
- 실행마다 `/api/test/reset`으로 해당 계정의 장바구니·쿠폰·찜·세션을 비운 뒤 새 BrowserContext에서 로그인한다.
- B01의 화면 중복 방지 상태는 CartView가 재생성될 때 사라진다. 새로고침 외에 다른 페이지로 나갔다 돌아오는 경로도 발동한다.
- B01의 서버 검증 누락 범위는 **장바구니에 상품 1이 포함된 경우**다. 다른 상품을 함께 담아도 쿠폰 결함은 발생한다. 금액 비교는 단일 상품으로 한다.
- B02는 상품 2의 감소 요청에만 발생한다. 다른 상품 추가·삭제·수량 변경처럼 합계를 다시 계산하는 작업은 잘못된 합계를 복구할 수 있다.
- B03은 같은 상세 컴포넌트를 재사용해야 한다. 추천 링크 대신 `page.goto('/products/3')`로 새 문서를 열면 재현되지 않는다.
- B04는 일반 목록에는 없는 **검색 결과 빠른 담기** 경로다. 한 번 클릭한 뒤 두 작업 모두 끝나 `aria-busy=false`가 될 때까지 기다린다. 연타는 필요 없다.
- B05의 해제는 `aria-pressed=false`뿐 아니라 요청 완료(버튼 활성화)까지 기다린다. 서버에는 항목이 남아 있고 다음 새로고침에서 복원된다.
- B06은 홈에서 실제 링크를 눌러 진입해 뒤로 가기 이력을 만든다. 팝업을 열고 `page.goto('/')`로 전체 문서를 새로 열면 전역 상태도 사라진다.
- 중간부터 실행해 선행 조건이 누락된 것을 재현 불가 제품 결함으로 취급하지 않는다.

## 3. 구현 위치·원인·수정 방향

| ID | 구현 위치 | 원인 | 실제 수정 방향 |
|---|---|---|---|
| B01 | `src/views/CartView.vue`, `server/src/services/cartService.js` | 적용 코드 Set을 서버 이력에서 복원하지 않음. 키보드 쿠폰 경로는 화면의 중복 방지만 신뢰 | UI를 서버 이력과 동기화하고, 서버는 상품과 무관하게 코드 중복 검증. 기존 중복 이력 정리 후 `(user_id, code)` 유일 제약 검토 |
| B02 | `server/src/services/cartService.js` | 마우스 감소 시 이전 subtotal 캐시 유지 | 감소 시에도 재계산 결과 저장 |
| B03 | `src/views/ProductDetailView.vue` | 한정판 상세 갱신 시 `purchaseSoldOut`을 이전 상품 값으로 유지 | 현재 상품의 `soldOut`에서 버튼 상태 계산 |
| B04 | `src/components/ProductCard.vue` | 허브 카드의 상위 위임 리스너와 버튼 리스너가 같은 작업을 각각 전달 | 단일 이벤트 처리 경로로 통합하거나 전파 차단 |
| B05 | `src/stores/favorites.js` | 매트 찜 복원 시 찜 UUID를 상품 ID로 덮어씀. 삭제 404를 이미 삭제된 것으로 오인해 낙관적 해제 유지 | 서버의 찜 ID 유지, 삭제 실패 시 화면 복구·오류 표시 |
| B06 | `src/components/DeliveryDialog.vue` | 받침대 전역 팝업을 라우트 변경 시 닫지 않음 | 모든 상품에 동일한 라우트 이탈 정리 적용 |

서버의 재고 검증·찜 API 자체는 정상이다. B03은 품절 상품이 실제 담기는 결함이 아니고, B05는 서버 삭제 API가 데이터를 무시하는 결함이 아니다.
결함 위치에는 `INJECTED DEFECT B0x` 주석을 두며 화면·API 응답에는 정답이나 결함 ID를 노출하지 않는다.

## 4. 제거·축소한 이전 결함

- **v1 B03 빈 검색 결과 잔류 제거**: 응답이 `items: []`이어도 이전 카드를 비우고 빈 결과 안내를 표시한다. v2 B03은 상세 상태 잔류이며 과거 보고서는 문서 버전을 확인한다.
- **전 상품 쿠폰 중복 적용 제거**: 키보드 포함 장바구니에서 B01 선행 조건으로만 시연한다. 다른 장바구니는 서버가 409를 반환한다.
- **전 상품 수량 감소 합계 오류 제거**: 상품 2 감소로만 제한했다.
- **미정의 장바구니 경로의 비로그인 401 제거**: 등록되지 않은 `/api/cart/*`도 404다. 정의된 장바구니 API는 계속 인증이 필요하다.
- 정상 품절 정책 N01은 `/products/3` 직접 진입에서 유지한다. 버튼 비활성화 자체는 결함이 아니다.

## 5. 검증

`tests/demo_browser.py`는 임시 dev/production DB와 정상 화면 로그인을 사용한다. 각 B01~B06, 검색·다른 상품·정상 진입 경로를 검사하고 스크린샷·관찰값 JSON을 임시 폴더에 남긴다.
실행 명령·실제 검증 결과는 [검증 기록](./DEMO_VERIFICATION.md)을 참고한다. 브라우저 검증은 SPEAR 엔진 실행·신고 위젯 통합 검증과 구분한다.
