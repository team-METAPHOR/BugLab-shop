# 상품별 결함 검증 기록 (팀 전용)

검증일: 2026-11-05. 대상: v2 결함 6개와 정상 대조 경로.
이 문서는 실제 관찰값을 포함하므로 AI·엔진의 제보/판정 입력으로 사용하지 않는다.

## 실행 결과

| 검사 | 결과 | 범위 |
|---|---|---|
| `npm run build` | 통과 | Vue/Vite 정적 빌드 |
| `npm --prefix server test` | 5/5 통과 | 검색, 혼합 장바구니 재계산, 쿠폰 범위, 찜 UUID·중복·소유권, 계정별 초기화·세션 무효화·미정의 API |
| `python tests/demo_browser.py --repeat 2` | 28/28 통과 | dev·production 각각 B01~B06 및 정상 대조 묶음을 2회씩 실행 |

브라우저: Chromium, viewport 1440×1000, reduced-motion=reduce.
검증 스크립트가 임시 DB·동적 포트·검증용 빌드 식별자를 가진 서버를 실행하고 종료했다.
dev는 reset 후 qa1 정상 화면 로그인, production은 매 시나리오 별도의 가상 계정을 화면에서 가입했다.
기존 `.env` 파일·서버 DB·실행 중인 서버는 사용하거나 수정하지 않았다. 비밀번호·토큰·쿠키는 결과에 기록하지 않았다.

| B06 | 뒤로 가기 후 URL은 홈. 받침대 배송 팝업이 그대로 화면을 가림. 스크린샷으로 확인 |

## 정상 대조와 제거한 결함

- 전체 목록 6개 → 키보드 2개 → 냉장고 0개·빈 결과 안내. 빈 검색 URL 새로고침도 정상.
- 상품 1·4·5·6의 수량 2→1에서 subtotal이 단가로 정상 복원. 혼합 장바구니의 정상 상품 변경도 재계산.
- 키보드 없는 장바구니는 새로고침 뒤에도 쿠폰 중복 적용 거부.
- 허브 상세 담기는 1개. 마우스 검색 빠른 담기도 1개.
- 매트의 추가 직후 찜 해제, 허브의 새로고침 후 찜 해제는 서버에도 반영되며 재새로고침해도 유지.
- 배송 팝업은 모든 상품에서 X로 정상 닫히고 열기 버튼으로 포커스 복귀. 받침대도 Escape·배경 클릭으로 닫힘. 마우스 팝업을 열고 뒤로 가면 정상 정리.
- 한정판 직접 진입은 품절 버튼 비활성화. 서버 재고 검증도 정상.
- 찜 API는 UUID로 해제하며 다른 사용자 항목 삭제를 거부. qa1 초기화 후 qa2 장바구니·쿠폰·찜·세션 보존.
- 잘못된 초기화 토큰은 401. production의 `/api/test/reset`은 404. 미정의 `/api/cart/unknown`은 비로그인도 404.
- 실행 중 예상하지 않은 브라우저 JavaScript 오류 없음.

## 산출물과 재실행

최종 빌드 28건 검증의 관찰값 JSON·스크린샷·서버 로그는 로컬 `/private/tmp/buglab-six-defects-final-verified/`에 있다.
임시 파일이므로 장기 보존이나 다른 PC에서의 접근은 보장하지 않는다. 재실행하면 새 산출물을 만든다.

```sh
npm run build
npm --prefix server test
# Python Playwright와 Chromium이 설치된 가상환경에서:
python tests/demo_browser.py --repeat 2
```

출력 위치를 고정하려면 `--output /tmp/buglab-demo-check`를 지정한다. 테스트 계정 비밀번호나 토큰을 명령행에 넣지 않는다.

## 검증하지 않은 범위

- SPEAR/Core_engine 실제 실행, 신고 위젯 → AI 질문 → 개발자 보고서의 통합 흐름.

- 실제 수정 커밋 배포 후 동일 계획 재검증.
- 정보 부족/인증 조건 부족으로 재현을 보류하는 두 번째 시연. 이번 범위는 정상 로그인과 재현 가능한 6개 결함이다.

브라우저 재현 통과를 위 항목의 통과로 표시하지 않는다. 엔진 연동 조건은 `PLAYWRIGHT_CONTRACT.md`를 따른다.
